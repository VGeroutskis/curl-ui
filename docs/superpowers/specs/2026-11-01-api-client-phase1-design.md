# curl UI ως API client: φάση 1

Κατάσταση: προς έγκριση. Στόχος έκδοσης: `0.4.0`.

## 1. Σκοπός

Το curl UI γίνεται δημόσια εναλλακτική του Postman για την καθημερινή δουλειά με
API, κρατώντας το δικό του πλεονέκτημα: τρέχει το πραγματικό curl του χρήστη, με
και τις 278 επιλογές και τα docs τους.

**Επιτυχία σημαίνει** ότι κάποιος μπορεί να φτιάξει, να οργανώσει, να τρέξει και να
ξαναβρεί αιτήματα με μεταβλητές χωρίς να ανοίξει το Postman, και ότι κάθε αίτημα
είναι μια εντολή curl που μπορεί να αντιγράψει και να τρέξει.

Η φάση 2, αμέσως μετά, είναι η εισαγωγή συλλογών από το Postman. Η φάση 1 δεν την
υλοποιεί, αλλά το μοντέλο της πρέπει να τη χωρά.

## 2. Αποφάσεις που έχουν κλειδώσει

| Θέμα | Απόφαση |
|---|---|
| Μοντέλο | Οι φόρμες είναι όψεις των επιλογών του curl. Υπάρχει μία αλήθεια: URL, method, επιλογές. |
| Εκτέλεση | Πάντα το πρόγραμμα curl, με πίνακα ορισμάτων και χωρίς shell. Όχι libcurl. |
| Δεδομένα | Τοπικά, χωρίς λογαριασμό, cloud ή telemetry. |
| Τεχνολογία | C11, SDL2, Nuklear. Καμία νέα εξωτερική βιβλιοθήκη. |
| Μεταβλητές | Μόνο από τον πίνακα της εφαρμογής. Το λειτουργικό δεν τις διαβάζει και δεν τις λαμβάνει. |
| Μεταβλητή που λείπει | Modal που ζητά την τιμή, τη γράφει στον πίνακα και συνεχίζει. |
| Τελική εντολή | Το curl και το Copy έχουν την πραγματική τιμή, όχι το `{{token}}`. |
| Secrets | Αστεράκια στην οθόνη, με ματάκι για προβολή. |
| Περιβάλλον του curl | Το curl σέβεται το `HTTP_PROXY`, το `~/.curlrc` κ.λπ. όπως στο τερματικό. Το «Ignore ~/.curlrc» μένει. |
| Params | Κωδικοποιούνται σε URL encoding. |
| Basic auth | Στο δίκτυο `Authorization: Basic base64(username:password)`, μέσω `--user`. |

## 3. Διάταξη

```
┌ Header ──────────────────────────────── Περιβάλλον: [Dev ▾] ┐
├ Tabs:  [GET users ×] [POST login • ×] [Variables ×] [+]     ┤
├──────────────┬────────────────────────────────┬─────────────┤
│ Collections  │ [POST ▾] {{base}}/login  [Run] │             │
│ History      │ Params Headers Body Auth Curl  │    Docs     │
│ Options      │ ...φόρμα ή κάρτες επιλογών...  │             │
│              │ Command                 [👁]   │             │
│              │ Response / Log                 │             │
└──────────────┴────────────────────────────────┴─────────────┘
```

- **Αριστερά:** Collections, History, και η σημερινή λίστα ως Options, με το
  φιλτράρισμα «μόνο ό,τι συνδυάζεται» όπως είναι. Ό,τι προσθέτουν οι φόρμες μετρά ως
  επιλεγμένο.
- **Κέντρο:** οι φόρμες, και στο **Curl** οι σημερινές κάρτες. Το Recipes μένει εκεί.
- **Δεξιά:** τα docs. Με hover σε γραμμή Headers εμφανίζονται τα docs του `--header`,
  και αντίστοιχα στις υπόλοιπες φόρμες.
- **Variables:** ειδικό tab, που ανοίγει από τον επιλογέα περιβάλλοντος.
- **Συντομεύσεις:** Ctrl/Cmd+S αποθήκευση, +T νέο tab, +W κλείσιμο, +Enter εκτέλεση.

Το ελάχιστο πλάτος των 1180 μονάδων παραμένει.

## 4. Αρχιτεκτονική

### Νέα modules στον πυρήνα (`src/core`, χωρίς SDL, με τεστ)

| Module | Ευθύνη |
|---|---|
| `json` | Parser σε δέντρο και writer. Βάθος έως 64. Σφάλμα με γραμμή και στήλη. Ο `json_fmt` μένει για τη μορφοποίηση αποκρίσεων. |
| `vars` | Περιβάλλοντα, μεταβλητές, εύρεση `{{όνομα}}`, αντικατάσταση, λίστα όσων λείπουν. |
| `mask` | Από κείμενο με secrets σε κείμενο για εμφάνιση. |
| `urlquery` | Ανάλυση query σε γραμμές και σύνθεση με URL encoding. |
| `forms` | Μετατροπή Headers, Body και Auth από και προς επιλογές του `request`. |
| `collection` | Δέντρο συλλογών, ανάγνωση και εγγραφή. |
| `history` | Ιστορικό σε αρχείο, με όριο 500. |
| `cmdparse` | Ανάλυση εντολής curl σε `request`. |

Η ατομική εγγραφή ιδιωτικού αρχείου από το `settings.c` γίνεται κοινή συνάρτηση.

### Tabs

Από το `app_t` μεταφέρονται στο νέο `tab_t`: το αίτημα και η method, η κατάσταση των
καρτών και των φορμών, η διεργασία, τα buffers εξόδου, τα αποτελέσματα εκτέλεσης και
τα wrap caches. Το `app_t` κρατά πίνακα έως 32 tabs και δείκτη στο ενεργό. Το
`app_poll` ελέγχει όλα τα tabs, οπότε μπορούν να τρέχουν ταυτόχρονα. Το όριο των 8 MB
απόκρισης ισχύει ανά tab.

### Ροή εκτέλεσης

```
αίτημα με {{...}}
  → εύρεση μεταβλητών που λείπουν → αν υπάρχουν: modal, χωρίς εκτέλεση
  → αντικατάσταση                  → πίνακας ορισμάτων με τις πραγματικές τιμές → curl
  → προβολή με μάσκα               → Command στην οθόνη
```

Το `builder` συνεχίζει να παίρνει `request`. Η αντικατάσταση δουλεύει σε αντίγραφο,
οπότε το αποθηκευμένο αίτημα κρατά πάντα το `{{token}}`. Το προσωρινό αντίγραφο
σβήνεται με `free` μετά το ξεκίνημα της διεργασίας και δεν γράφεται σε αρχείο.

## 5. Μεταβλητές

- **Σύνταξη:** `{{όνομα}}`, όπου το όνομα ταιριάζει με `[A-Za-z0-9_.-]+`. Ό,τι άλλο,
  όπως το `{{"a":1}}`, μένει κείμενο.
- **Πού ισχύουν:** URL και κάθε τιμή επιλογής.
- **Ένα πέρασμα:** τιμή που περιέχει `{{x}}` δεν ξαναεπεξεργάζεται.
- **Κάθε περιβάλλον** έχει δικό του πίνακα. Μεταβλητές συλλογής και global δεν υπάρχουν
  στη φάση 1. Στη φάση 2, οι εισαγόμενες θα μπαίνουν σε περιβάλλον.
- **Περιβάλλον `Default`:** υπάρχει πάντα ένα ενεργό. Προσθήκη, μετονομασία, αντιγραφή
  και διαγραφή με επιβεβαίωση. Το τελευταίο δεν διαγράφεται.

### Πίνακας Variables

Στήλες Όνομα, Τιμή, Secret, ματάκι, διαγραφή. Τιμή secret εμφανίζεται με αστεράκια.
Μη έγκυρο ή διπλό όνομα σημαίνεται στη γραμμή και δεν αποθηκεύεται.

### Modal για ό,τι λείπει

Μετά το Run, αν λείπουν μεταβλητές από το ενεργό περιβάλλον:

1. Δεν ξεκινά καμία διεργασία. Το modal δείχνει το περιβάλλον και μια γραμμή για κάθε
   μεταβλητή: πεδίο τιμής και κουτάκι Secret.
2. Το Secret είναι προεπιλεγμένο αν το όνομα περιέχει, χωρίς διάκριση πεζών-κεφαλαίων,
   `token`, `secret`, `password`, `passwd`, `key` ή `auth`.
3. **Save & Run:** γράφει στον πίνακα, αποθηκεύει το αρχείο και εκτελεί. Κενή τιμή
   επιτρέπεται, αφού μπορεί να είναι σκόπιμη.
4. **Cancel:** τίποτα δεν αλλάζει.
5. **Open Variables:** κλείνει το modal χωρίς εκτέλεση και ανοίγει τον πίνακα.

### Secrets στην έξοδο

| Σημείο | Τι φαίνεται |
|---|---|
| Curl που εκτελείται | Πραγματική τιμή |
| Command στην οθόνη | Αστεράκια. Το ματάκι τα δείχνει μέχρι να αλλάξει tab. |
| Copy στο Command | Πραγματική τιμή, με σύντομο μήνυμα ότι περιέχει secrets |
| Response και Log, οθόνη και Copy | Καλυμμένα, χωρίς ματάκι |
| Συλλογές, ιστορικό, αρχείο tabs | `{{όνομα}}`, ποτέ η τιμή |
| Αρχείο του `--output` | Ό,τι στείλει ο server, χωρίς κάλυψη |

Η κάλυψη εξόδου γίνεται κατά την εμφάνιση, γραμμή προς γραμμή, και πιάνει:
- την ακριβή τιμή,
- την τιμή σε URL encoding,
- το `base64(username:password)` όταν κάποιο από τα δύο περιέχει secret.

Τιμές με λιγότερους από 4 χαρακτήρες δεν καλύπτονται στην έξοδο, γιατί θα κάλυπταν
τυχαίο κείμενο. Ο πίνακας το δηλώνει στη γραμμή.

## 6. Φόρμες

Κάθε φόρμα διαβάζει και γράφει επιλογές του `request`. Για ό,τι δεν εκφράζεται σε
επιλογή, το αίτημα κρατά πρόσθετα στοιχεία που δεν μπαίνουν στην εντολή: τις
απενεργοποιημένες γραμμές και τον τύπο του Auth (`form_hints`).

### Params

- Ο πίνακας Κλειδί/Τιμή με ενεργοποίηση ανά γραμμή συγχρονίζεται με το query του URL.
- Από τον πίνακα προς το URL, κλειδί και τιμή κωδικοποιούνται χωριστά σε UTF-8. Μένουν
  ως έχουν μόνο τα `A-Z a-z 0-9 - _ . ~`, το κενό γίνεται `%20` και το `{{...}}` μένει
  αυτούσιο.
- Από το URL προς τον πίνακα, `%XX` και `+` αποκωδικοποιούνται, και άκυρο `%` μένει ως
  έχει. Δεν γίνεται ποτέ διπλό encoding.
- Το κείμενο της μπάρας δεν ξαναγράφεται αν δεν αλλάξει ο πίνακας.
- **Αντικατάσταση:** μέσα στο query, η τιμή της μεταβλητής κωδικοποιείται. Πριν από το
  `?` μπαίνει ως έχει, ώστε το `{{base}}` να μπορεί να περιέχει `https://host/api`.
- Το fragment `#...` μένει στο τέλος.

### Headers

Πίνακας πάνω στα `--header`, με ενεργοποίηση ανά γραμμή.

### Body

| Τύπος | Επιλογή curl |
|---|---|
| none | καμία |
| raw | `--data-raw`, με προαιρετικό `Content-Type` ως header |
| JSON | `--json` |
| form-data | `--form-string name=value` για κείμενο, `--form name=@path` για αρχείο |
| urlencoded | `--data-urlencode`, όπου η φόρμα κωδικοποιεί η ίδια το όνομα |
| file | `--data-binary @path` |

Δεν υπάρχει όριο στο μέγεθος του σώματος από την εφαρμογή, βλ. §6α.

### Auth

| Τύπος | Επιλογή curl | Κανόνες |
|---|---|---|
| none | καμία | |
| Basic | `--basic --user user:pass` | Username με `:` είναι σφάλμα. UTF-8. |
| Bearer | `--oauth2-bearer` | |
| Digest | `--digest --user user:pass` | Ίδιος κανόνας για το username. |
| API key | Header ή query, κατ' επιλογή | |

- Προειδοποίηση όταν το URL δεν είναι `https://`: το base64 δεν είναι κρυπτογράφηση.
- Προειδοποίηση όταν το password ή το token είναι γραμμένο απευθείας και όχι ως
  μεταβλητή, γιατί τότε μπαίνει αυτούσιο σε ιστορικό και συλλογές.

### Κατάσταση που δεν χωρά σε φόρμα

Αν οι επιλογές δεν εκφράζονται από τη φόρμα, π.χ. `--data` μαζί με `--form` ή άλλη
μέθοδος auth, η φόρμα δείχνει «Set by options», τις επιλογές αυτές και ένα κουμπί προς
το Curl. Δεν αλλάζει και δεν σβήνει τίποτα μόνη της. Η αλλαγή τύπου Body ή Auth αφαιρεί
τις επιλογές του προηγούμενου τύπου μόνο όταν η φόρμα τις εκφράζει πλήρως.

## 6α. Χωρίς όριο μεγέθους τιμών

Τα σταθερά όρια της εφαρμογής (16 KB ανά τιμή, 8 KB στο URL) καταργούνται: τιμές και URL
είναι δυναμικά και μεγαλώνουν όσο χρειάζεται, και ισχύει το ίδιο στη φόρτωση αρχείων.

Το λειτουργικό έχει όμως δικά του όρια στα ορίσματα. Μετρημένο στο Linux, ένα όρισμα 131.000
bytes περνά και ένα 132.000 απορρίπτεται. Στα Windows η γραμμή εντολών έχει όριο 32.767
χαρακτήρες. Γι' αυτό:

- **Όταν ένα όρισμα ξεπερνά τα 100.000 bytes, το σύνολο τα 200.000, ή η γραμμή εντολών των
  Windows τους 30.000 χαρακτήρες,** όλα τα ορίσματα εκτός από το `--disable` γράφονται σε
  ιδιωτικό προσωρινό αρχείο config στον φάκελο ρυθμίσεων, και το curl το διαβάζει με
  `--config`. Το αρχείο σβήνεται όταν τελειώσει η εκτέλεση, και όσα τυχόν έμειναν από κατάρρευση
  σβήνονται στην εκκίνηση.
- **Όριο του ίδιου του curl:** μια γραμμή config φτάνει τα 10 MB (`MAX_CONFIG_LINE_LENGTH`).
  Μετρημένο: 9 MB περνούν, 11 MB απορρίπτονται. Αν κάποιο όρισμα το ξεπερνά, το Run δεν ξεκινά και
  το μήνυμα προτείνει Body τύπου file ή `@αρχείο`, όπου το curl διαβάζει το αρχείο απευθείας.
- **Το Command και το Copy** δείχνουν την κανονική εντολή. Στο πανέλ, τιμή μεγαλύτερη από 2.000
  χαρακτήρες κόβεται με ένδειξη μεγέθους, ενώ το Copy δίνει ολόκληρη την εντολή.

## 7. Συλλογές, tabs και ιστορικό

### Συλλογές

- Δέντρο συλλογών, φακέλων και αιτημάτων, με αναζήτηση, μετονομασία, αντιγραφή,
  διαγραφή με επιβεβαίωση και μετακίνηση από μενού. Χωρίς σύρσιμο.
- Νέα αποθήκευση ζητά όνομα και θέση.
- Tab με αλλαγές έχει τελεία. Το κλείσιμό του ρωτά Save, Discard ή Cancel.
- Δύο tabs στο ίδιο αποθηκευμένο αίτημα δεν ανοίγουν: το κλικ πηγαίνει στο υπάρχον.

### Tabs

Ξανανοίγουν στην επόμενη εκκίνηση με τις μη αποθηκευμένες αλλαγές τους, χωρίς τις
αποκρίσεις. Η ρύθμιση **Reopen tabs** (`reopen_tabs`, προεπιλογή On) αντικαθιστά το
Remember the last request. Με Off, το αρχείο tabs σβήνεται στο κλείσιμο, και τα tabs με
αλλαγές ρωτούν πριν από το κλείσιμο της εφαρμογής. Ένα υπάρχον `last-request.txt`, αν
το `remember_request` ήταν On, ανοίγει μία φορά ως tab και μετά σβήνεται.

### Ιστορικό

Τα τελευταία 500 αιτήματα, με ώρα, status, χρόνο, μέγεθος και το αίτημα με `{{όνομα}}`,
χωρίς αποκρίσεις. Κλικ ανοίγει νέο tab. Το Clear history ζητά επιβεβαίωση.

## 8. Εισαγωγή εντολής curl

Modal με επικόλληση. Το αποτέλεσμα ανοίγει σε νέο tab. Δεν εκτελείται ποτέ shell.

- **Δέχεται:** προαιρετικό αρχικό `curl`, μονά και διπλά εισαγωγικά, `\` και συνέχιση
  γραμμής με `\`, μακριές και σύντομες επιλογές, ομάδες όπως `-sSL`, κολλημένη τιμή όπως
  `-XPOST` και `-d@file`, τις μορφές `--no-x`.
- **Σφάλμα με όνομα, χωρίς μερική εισαγωγή:** άγνωστη επιλογή, έλλειψη τιμής, ανοιχτό
  εισαγωγικό, `--next` ή πολλά URL, και, έξω από μονά εισαγωγικά, `$`, backtick, ή τα
  `|`, `;`, `&`, `<`, `>`.
- **`-X`:** γίνεται η method του αιτήματος.
- Η μορφή `^` του Windows cmd δεν υποστηρίζεται στη φάση 1 και δίνει σφάλμα.

## 9. Αρχεία

Στον φάκελο ρυθμίσεων, όλα ιδιωτικά (0600 σε Linux και macOS) και με ατομική εγγραφή:

| Αρχείο | Περιέχει |
|---|---|
| `settings.ini` | Όπως σήμερα, μαζί με `reopen_tabs` |
| `variables.json` | Περιβάλλοντα και τιμές, σε απλό κείμενο |
| `collections/<id>.json` | Μία συλλογή |
| `session.json` | Ανοιχτά tabs |
| `history.jsonl` | Μία εγγραφή ανά γραμμή |

Μορφή συλλογής:

```json
{
  "format": "curl-ui-collection",
  "version": 1,
  "name": "My API",
  "items": [
    {
      "type": "folder",
      "name": "Auth",
      "items": [
        {
          "type": "request",
          "name": "Login",
          "method": "POST",
          "url": "{{base}}/login",
          "options": [
            { "name": "json", "values": ["{\"user\":\"{{user}}\"}"] },
            { "name": "location", "negated": false, "values": [] }
          ],
          "form_hints": { "auth": "none", "disabled_params": [], "disabled_headers": [] }
        }
      ]
    }
  ]
}
```

Οι επιλογές αποθηκεύονται με το μακρύ τους όνομα, στη σειρά τους.

### Σφάλματα αρχείων

- **Κατεστραμμένο αρχείο:** μετονομάζεται σε `<όνομα>.bad-<αριθμός>`, δεν αντικαθίσταται,
  και μια ειδοποίηση λέει τι έγινε και πού είναι.
- **Νεότερο `version`:** η συλλογή ανοίγει μόνο για ανάγνωση.
- **Άγνωστη επιλογή σε συλλογή,** π.χ. από νεότερο curl: κρατιέται στο αρχείο και το tab
  το δείχνει, αντί να χαθεί στην αποθήκευση.
- **Αποτυχία εγγραφής:** το σφάλμα εμφανίζεται και το tab μένει με αλλαγές.

## 10. Γνωστά όρια

Θα αναφέρονται και στο README:

- Οι τιμές του πίνακα είναι σε απλό κείμενο, σε αρχείο που διαβάζει μόνο ο λογαριασμός
  του χρήστη. Δεν προστατεύονται από κάτι που τρέχει με τον ίδιο λογαριασμό.
- Κατά το Run, οι τιμές περνούν ως ορίσματα στο curl, οπότε μπορεί να τις δουν άλλες
  διεργασίες στο ίδιο μηχάνημα, όπως και στο τερματικό.
- Η κάλυψη εξόδου δεν είναι εγγύηση: δεν πιάνει άλλες κωδικοποιήσεις, ούτε τιμή που
  χωρίζεται σε γραμμές.
- Κείμενο που πρέπει να σταλεί αυτούσιο ως `{{x}}` δεν υποστηρίζεται: θα ζητηθεί τιμή.
- Τιμή που είναι ήδη κωδικοποιημένη, όταν μπαίνει σε query, κωδικοποιείται ξανά.
- Τα αρχεία είναι τοπικά. Η κοινή χρήση με Git και η εξαγωγή έρχονται στη φάση 2.
- Τιμή πάνω από 10 MB στέλνεται μόνο από αρχείο, λόγω του ορίου του curl (§6α).
- Το προσωρινό αρχείο του §6α περιέχει τις πραγματικές τιμές, και τα secrets, όσο τρέχει το
  αίτημα. Μια κατάρρευση μπορεί να το αφήσει μέχρι την επόμενη εκκίνηση.
- Μια εντολή με τεράστια τιμή που αντιγράφεται μπορεί να μην τρέχει στο τερματικό, λόγω του
  ίδιου ορίου του λειτουργικού.
- Τα μεγάλα αιτήματα μεγαλώνουν αντίστοιχα το ιστορικό και τις συλλογές στον δίσκο.

## 12. Έλεγχος

**Μονάδες (`ctest`, σε όλες τις πλατφόρμες του CI):**
- `json`: έγκυρα, άκυρα, βάθος, UTF-8, escape, επαναφορά χωρίς απώλεια.
- `vars`: εύρεση, μη έγκυρα ονόματα, ένα πέρασμα, ό,τι λείπει.
- `urlquery`: encoding, ελληνικά, `&`, `=`, `+`, άκυρο `%`, fragment, επαναφορά χωρίς διπλό
  encoding.
- `mask`: ακριβής τιμή, URL encoding, base64, κοντές τιμές.
- `forms`: κάθε τύπος και η «Set by options».
- `cmdparse`: όλα όσα δέχεται και όλα όσα απορρίπτει.
- `collection`, `history`, `session`: αποθήκευση και φόρτωση, κατεστραμμένα αρχεία, όριο 500.

**Τεστ που πρέπει να μην περάσει ποτέ λάθος:** μια μοναδική secret τιμή περνά από εκτέλεση,
αποθήκευση, ιστορικό και tabs, και το τεστ ελέγχει ότι δεν εμφανίζεται σε κανένα αρχείο
εκτός του `variables.json`.

**Πραγματικό curl με τοπικό server (`echoargs` και mock):**
- Το header που φτάνει είναι ακριβώς `Basic base64(username:password)`.
- Το query φτάνει σωστά κωδικοποιημένο.
- Κάθε τύπος Body και Auth φτάνει όπως πρέπει.
- Το αίτημα δεν ξεκινά όσο λείπει μεταβλητή.

**Εφαρμογή με scripted είσοδο:** ροή του modal έως το Save & Run, ταυτόχρονη εκτέλεση σε
tabs, αποθήκευση και επανάνοιγμα, ματάκι. Το `test_args` για όλες τις επιλογές μένει ως
έχει, και τρέχουν και τα sanitizers. Το πλήρες `live_options.py` ξανατρέχει πριν από το
release της `0.4.0`.

**Μη αυτοματοποιημένα:** η χρήση με το χέρι σε κάθε πλατφόρμα δεν καλύπτεται από το CI και
θα δηλωθεί ως τέτοια.
